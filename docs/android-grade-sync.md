# Android native grade sync

Android grade sync follows the chosen foreground-only policy: edits are durable locally while the app is away; returning to the app reconciles both directions. There is no bcorn background sync service, WorkManager job, alarm, relay, push receiver, or server. The official Google SDK can merge its own protected authorization/revocation components; these are not a bcorn background synchronization worker. The native layer checks resumed state independently of the renderer, invalidates queued consent/binding transitions across a pause, and cancels active HTTP on pause. An already-started atomic local save may finish, but its stale continuation cannot start network work. Cancellation cannot undo a request already accepted by Google; the journal retains pending changes so the shared coordinator verifies them on resume.

## Configuration gate

The production integration uses `com.google.android.gms:play-services-auth:22.0.0` and Google Identity Services `AuthorizationClient`, with `com.squareup.okhttp3:okhttp:4.12.0` for sticky per-request cancellation. Set the application's `com.acorn.widget.GRADE_SYNC_CONFIGURED` manifest metadata to true only after an operator has registered the real Android package/signing-certificate SHA-1 and enabled the Sheets, Drive and Google Picker APIs in the authorized Google project. The default is false. No client secret, Web client ID, redirect URI, browser login, or embedded WebView OAuth is used.

The previous signing key is unavailable. This change creates no replacement signing identity, Google project, credential, OAuth grant, or live account connection. An unsigned build verifies compilation and packaging, not an installable update or working live consent. A mismatched or missing Google client and missing Play Services remain explicit setup failures.

## Native authorization boundary

- The only requested scope is `https://www.googleapis.com/auth/drive.file`. Prior unrelated grants are explicitly excluded. No `openid`, email, profile, Calendar, full Drive or server/offline grant is requested. Native Google Picker uses that same `drive.file` scope, not a broader Picker scope.
- Explicit Connect invokes the SDK's account selector and native consent when required. SDK resolution is deferred while the Activity is paused. Cancelling or destroying the pending flow never creates a file afterward.
- A foreground session can call `authorize` without showing consent to obtain a fresh short-lived access token from previously granted access. A resolution required during automatic sync stops sync and asks for explicit reconnection.
- Google Play Services owns its token cache/renewal semantics. The app does not request, receive, store, or exchange refresh tokens or authorization codes. Access tokens stay in native memory, are cleared from app memory on pause, and are never exposed to JavaScript, error messages, logs, exports, or tests with live credentials.
- HTTP 401 clears the SDK's cached token. Bounded Google error-reason parsing distinguishes 403 quota/rate limits (retry/backoff) from file-permission failures (check/relink the bound file); neither falsely revokes the OAuth grant. There is no automatic consent or scope expansion.

Google's native authorization response does not identify the selected account under this scope. The app therefore never guesses identity from an email or token. Before using a newly acquired token, native code calls the fixed Drive `about.get?fields=user(permissionId)` projection, which officially supports the same `drive.file` scope. It hashes that opaque ID with the installation ID, stores only the fingerprint in encrypted binding state, and checks it against the selection or confirmed connection. The raw ID, fingerprint and token never enter public status or the renderer. A mismatch or missing identity fails closed before any file operation; legacy unpinned connections require explicit reconnect. Identity verification is cached only for the exact native token, and that cache is cleared on pause. Before either native account selector, any old binding is durably blocked. A cancelled or failed account switch retains the old journal but cannot resume it under a replacement account. The compatibility Connect path creates a brand-new 14-column spreadsheet. The human-readable template path creates a new four-column sheet. The separate native Picker path can inspect a future user-selected existing sheet; selection alone never binds or writes it. Only explicit mapping confirmation creates a fresh mapped connection ID, after another bounded read and validation. The particular personal spreadsheet supplied during development was never accessed, embedded or modified in these tests.

## Table and HTTP invariants

The compatibility create request mirrors `src/shared/sync-adapters/google-sheets.js`'s template: 1 tab, 1002 rows, 14 columns, frozen header row, exactly the documented headers. Title and tab are validated before SDK calls.

The renderer has only these capabilities:

- `getGradeSyncStatus()`: state, confirmed binding, opaque connection ID, installation ID, `automaticInbound: false`, foreground availability. It never returns account information or OAuth material.
- `connectGradeSheet({title, tab})`: explicit native authorization and creation of a new template. Caller-supplied spreadsheet IDs are rejected.
- `gradeSheetsRequest({method, path, body})`: rejects mapped bindings. For the compatibility binding, exact bound-file GET of `'tab'!A1:N1002`, or one RAW 14-column row PUT at rows 2–1001. Header edits, other files/tabs/ranges, batch updates, deletes, arbitrary hosts, extra query parameters, arbitrary headers, and nested cell bodies are rejected before authorization or network.
- `gradeSheetVersion()`: native-only Drive `files.get` for the currently bound file, returning only `version` and optional `modifiedTime`. It accepts no file ID or path. This lets visible adaptive polling avoid unchanged full-table reads.
- `loadGradeSyncState(connectionId)` / `saveGradeSyncState(connectionId, envelope)`: active-connection-only private journal. A prior connection cannot load or save through a new connection. Normal grade-book export does not include this journal.

### Native Picker and mapped mode

The official Android Picker uses `AuthorizationRequest.ResourceParameter.PICKER_OAUTH_TRIGGER`, spreadsheet MIME filtering, single-file selection, and `CONSENT | SELECT_ACCOUNT`. Only a single validated `picked_file_ids` value from the SDK's native token-response bundle is accepted. OAuth tokens, account identity and the selected spreadsheet ID never enter the renderer. No callback URL, WebView token or custom OAuth exchange is added.

- `pickGradeSheet({})` returns an ephemeral opaque selection ID and safe title/tab metadata. It performs no write and leaves prior sync blocked.
- `previewGradeSheet({selectionId, sheetId})` reads only the native-selected tab's fixed A1:Z200 window. All 5,200 cells are explicit, including blanks. Values are unformatted; formulas become boolean markers, not formula text. Merged/protected cells are marked. Unknown/named-only protection conservatively protects the entire window. The preview cannot request an arbitrary file, URL, tab or range.
- `confirmGradeSheetMapping({selectionId, mapping})` re-reads that window, validates the explicit mapping, and stores a new encrypted binding/connection. It performs no remote write. Public binding is `{kind: "mapped", mapping, tab, confirmed: true}`; its native spreadsheet ID stays private. Existing local courses are merged explicitly by the shared client, not overwritten by native confirmation.
- `readMappedGradeSnapshot({connectionId})` returns only the bound fixed-window snapshot. `commitMappedGradeCells({connectionId, expectedSnapshot, writes})` ignores renderer-supplied mappings: the confirmed mapping is loaded from native storage. It re-reads, compares mapped target values/safety and exact label anchors, writes only selected mapped grade/weight cells with RAW `values:batchUpdate`, and verifies a fresh readback before reporting success.
- `createMappedGradeSheet({course})` validates a bounded grade-book course and derives a human-readable Assessment / Weight / Grade / Contribution template natively. Renderer-provided formulas, arbitrary rows or mappings are not accepted. New sheet creation is explicit, never a fallback for a failed read. Original 14-column bindings remain a separate compatibility mode.

Mapped writes reject unknown/duplicate/out-of-window cells, changed labels, formulas, merged/protected destinations, stale snapshots, wrong connection IDs and invalid grade/weight values. Empty grade and genuine zero remain distinct. Points are a validated literal fraction; naked numeric grades follow the confirmed ratio/percentage interpretation. Titles, totals, notes, labels and formula cells are outside the write allowlist. Large preview/mapping parsing and encryption run on the serial state executor rather than the UI thread.

**Concurrency limitation:** Google Sheets `values:batchUpdate` has no atomic cell compare-and-swap. Another editor can insert or change a formula after the preflight read and before the RAW write. Readback detects a mismatched result, but cannot guarantee that such a concurrent edit was never overwritten. A newly created template also requires exact initial grade/weight readback, including zero versus blank, before its connection is stored. The UI must disclose this before mapping confirmation; it must not promise transactional protection.

OkHttp calls are registered before the final foreground check, so cancelling before execute remains cancelled. The network origin is fixed to Sheets, with fixed Drive file-version and native account-fingerprint metadata routes. Broader mapped operations are constructed from native selection/binding state, never from renderer paths. TLS uses the platform trust store, redirects are disabled, and cookies, caching, user-supplied headers and certificate overrides are absent. Responses are bounded to 4 MiB; error bodies and unrelated response fields are discarded. RAW means a title starting with `=` is text, not a formula.

## Private state

`EncryptedGradeSyncStorage` keeps device ID, binding and per-connection journals under the app's no-backup private directory. Android Keystore provides a non-exportable AES-256 key; AES-GCM gives each write a fresh IV and authenticates the file's purpose/name. Copying a different connection's ciphertext cannot transplant its outbox. AtomicFile preserves the previous complete write after interruption. A single process-wide store keeps connection metadata coherent across Activity recreation; key creation, metadata changes, and journal encryption run on a serial disk executor rather than the UI thread.

Each journal is at most 4 MiB with schema version 1 and only `coordinator` and `publishedBook` at the envelope boundary. Nested data has a depth/size bound and rejects prototype keys and credential-shaped fields. Corrupt, oversized, wrong-version or wrong-connection input is rejected without overwriting a good journal. Android backup/device transfer are disabled at the application level as well.

## Verification

On 2026-10-18 the complete production app was built with standard AGP against official Google Identity 22.0.0 / OkHttp 4.12.0 artifacts. The native host runner used the actual AGP Kotlin classes, generated R jar, merged manifest, unsigned APK resources/assets and exact resolved runtime graph. All 157 API35 host tests passed in each of two separate JVMs (314 runs), including 90 authorization/Picker/mapping/template tests and 4 complete-backup transport tests. The encrypted journal reload was exercised across the two JVMs. All 23 packaged renderer/shared/bridge asset files matched the frozen source bytes. This is production compilation/packaging and Android host verification, not real-device authorization.

`NativeGradeSyncTest.java`, `NativeGradePickerTest.java` and `NativeGradeMappedSheetPolicyTest.java` exercise synthetic SDK/transport seams, exact request boundaries, quota/auth failures, queued cancellation, account-switch isolation, immutable mapping, fresh/readback conflicts, exact new-template initialization, encrypted private disk, AES-GCM integrity/AAD, and response limits. The real cryptographic algorithm is tested with an injected synthetic key; the host environment does not prove Android Keystore hardware backing. Mock authorization does not prove a real Google consent or Picker flow.

The merged package requests exactly `INTERNET`, `READ_CALENDAR` and `WRITE_CALENDAR`. `MainActivity` is the exported launcher; the widget receiver, `SignInHubActivity` and `GoogleApiActivity` are non-exported. The only service is the official SDK's exported `RevocationBoundService`, protected by `com.google.android.gms.auth.api.signin.permission.REVOCATION_NOTIFICATION`. No analytics/advertising, account-list, boot, alarm, push or foreground-service permissions are added. The SDK callback is not an application sync worker. The shipped configuration metadata remains false.

Required real-device acceptance remains: original-key signed upgrade, configured Android OAuth client, Google Play Services available, consent cancel/return, foreground reconciliation after process death, account switch, revoked grant, deleted spreadsheet, loss/return of connectivity, and backgrounding during a request. Verify that the scope screen contains only the dedicated-file grant and that no WebView ever receives a token. No such live test was performed during implementation.

## Official references

- [Android authorization guide](https://developer.android.com/identity/authorization): authorization is separate from authentication, native consent, and repeated foreground `authorize` calls; server refresh tokens are inappropriate for this device-only design.
- [AuthorizationRequest.Builder](https://developers.google.com/android/reference/com/google/android/gms/auth/api/identity/AuthorizationRequest.Builder): narrow scopes, exclude prior scopes, native account selection.
- [AuthorizationClient](https://developers.google.com/android/reference/com/google/android/gms/auth/api/identity/AuthorizationClient): obtain native authorization, clear invalid tokens.
- [Sheets spreadsheets.create](https://developers.google.com/workspace/sheets/api/reference/rest/v4/spreadsheets/create) and [values.update](https://developers.google.com/workspace/sheets/api/reference/rest/v4/spreadsheets.values/update): dedicated file creation and RAW bounded values writes.
- [Drive about.get](https://developers.google.com/workspace/drive/api/reference/rest/v3/about/get) and [Drive User](https://developers.google.com/workspace/drive/api/reference/rest/v3/User): `drive.file`-authorized opaque permission ID used only for private account pinning.
- [Drive files.get](https://developers.google.com/workspace/drive/api/reference/rest/v3/files/get): field-limited version checks with the same dedicated-file scope.

- [Native Android Picker](https://developers.google.com/workspace/drive/picker/guides/desktop-mobile-picker#use_the_google_picker_with_android_apps): SDK resource parameters and native selected-file response, documented 2026-10-12.
- [Android Keystore](https://developer.android.com/privacy-and-security/keystore): non-exportable keys and keeping cryptography off the UI thread.
- [Drive error handling](https://developers.google.com/workspace/drive/api/guides/handle-errors): distinguish 403 quota reasons from file-permission problems.
