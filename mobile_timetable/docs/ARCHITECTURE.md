# 结构说明

这里按隐藏复杂性与缩小模块接口的方向组织代码，避免为了分层而增加空壳抽象。

- 领域层 `timetable.dart` 不依赖 Flutter、Android 或 iOS：承载重复规则、时间边界、排序、校验、JSON 和链接构造。页面和两个原生 widget 按同一数据协议计算，避免保存容易过时的“当前课程”字符串。
- 平台接口 `PlatformStore` 承载本机存储、外部链接、组件添加和待消费的课程跳转。UI 不知道 SharedPreferences/App Groups 的具体键或位置。
- 展示层分为可复用日程卡片、放大详情/上下文操作、课程编辑器。单击、长按和导航是不同的显式交互；后续上下文功能集中添加，不必往每张卡片堆按钮。
- `main.dart` 保留应用生命周期、页面选择与保存/删除/导入等操作协调。复杂输入、数据校验和平台存储各有明确归属。
- Android 在全量校验后同步提交本地快照，再尽力刷新组件。组件刷新失败不会让已持久化的保存误报失败。无精确闹钟和后台常驻服务。
- iOS 通过 App Group 共享快照，WidgetKit 提前生成课程边界时间线；不依赖应用持续运行。
- 组件→应用交接使用课程 ID 队列，Flutter 在加载后、恢复前台和原生提示时消费；已删除 ID 明确提示，不把不可信 URL 直接交给外部应用。
- 日期导航使用本地日历日期运算，避免以固定 24 小时跨夏令时导致周视图偏一天。

这不是完整多层企业架构。0.1 版仍以单一课表和全量 JSON 替换为边界。增加多个课表、学校导入或提醒前，应先明确数据迁移、认证授权与设备生命周期测试，保持现有模块接口简单。
